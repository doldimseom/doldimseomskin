## 1. 프로젝트 개요

* **주 수요층:** TRPG 향유층. 구체적으로는 세션에 참여해 **로그를 남기고, OC(캐릭터)를 운영·전시하고, 관계를 기록하는** 플레이어.
* **목표:** 티스토리 블로그의 형태를 벗어나 개인 홈페이지(갠홈) 감성을 내는 미니멀·모던 스킨. 유저의 자산(캐릭터 / 로그 / 관계)이 주인공이 되는 정보 구조.
* **기술 스택:** 바닐라 HTML / CSS / JS. 외부 라이브러리 최소화 (현행 스킨 기준 Pretendard + Lucide Icons만 사용).
* **개발 철학:** 코드보다 유저의 체감과 접근 경로(UI/UX)를 먼저 설계한다. 스킨 옵션은 늘리지 않고 직관적 조작감을 우선한다.

### 1.1. 비목표 (Non-goals)

명시적으로 이 스킨이 하지 않는 것 — 범위 팽창 방지용.

* 시나리오 집필·배포·판매를 위한 기능 일체 (집필용 가독성 템플릿, NPC 대화창 / 핸드아웃 삽입 CSS, 시나리오 갤러리 등)
* 커미션 수주 / 가격 표시 기능 → 기존 「돌딤섬 공방 스킨」의 영역
* 티스토리 에디터를 대체하는 별도 저작 도구

## 2. 티스토리 기본 요소 통제 및 카테고리 라우팅

이 스킨의 핵심은 '티스토리 블로그'처럼 보이지 않는 것.

### 2.1. 기본 UI 통제

공감(하트), 기본 댓글창, 구독 버튼, 하단 Powered by, 방명록, 우측 상단 툴바를 숨기거나 톤앤매너에 맞게 미니멀하게 개조한다.

* **현행 유지:** v1.2.0이 이미 CSS + `MutationObserver`로 공감(`.txt_like`, `[id^="reaction-"]`)을 처리하고 있음. 동일 방식 계승.
* **단서:** 관리자 진입 경로(로그인·글쓰기)는 **남긴다.** 완전 제거 시 운영자가 관리 화면에 못 들어간다. 아이콘 1개 수준으로 축소.
* **그리드/리스트 뷰 전환은 신규 항목이 아님.** v1.2.0에 `setLayout()` + `localStorage('ds-layout')`로 구현되어 있으며 그대로 재사용한다.

### 2.2. 카테고리 라우팅

유저가 스킨 편집 창에서 카테고리 이름을 지정하면, 스킨이 이를 감지해 해당 카테고리 접속 시 전용 템플릿을 출력한다.

* **라우팅 대상 (2종으로 축소):**
  * `캐릭터 카테고리` → 캐릭터 갤러리 템플릿
  * `로그 카테고리` → 로그 목록 / 로그 뷰어 템플릿
  * 그 외 카테고리 → 기본 카드 목록 (현행 v1.2.0 동작)
* **판정 방식:** 서버 라우팅이 없으므로 `location.pathname`의 `/category/{이름}` 파싱 + 카드의 `data-category` 속성 대조 (v1.2.0 `buildSections()` 방식 계승).
* **필수 예외 처리:**
  * 한글 카테고리명 URL 인코딩 (`decodeURIComponent` 필수)
  * 하위 카테고리 (`/category/부모/자식`) — 부모명 매칭 시 자식도 포함할지 옵션화
  * 홈 화면에서는 여러 카테고리가 한 페이지에 섞임 → 섹션 단위로 템플릿 적용
  * 유저가 카테고리명을 바꾸면 라우팅이 끊김 → **옵션 미입력 시 기본 템플릿으로 안전하게 폴백**

## 3. 핵심 기능 및 UX/UI 명세

### 3.1. 모듈형 블로그 홈

* **UX/UI:** 유저가 블록 장난감처럼 원하는 섹션만 골라 순서를 배치.
* **제공 모듈:** `[캐릭터 리스트형]`, `[로그 썸네일형]`, `[관계/페어 전시형]`, `[텍스트 공지사항]`
* **구현 방식 — 2안 병기 (§4.1 검증 결과에 따라 택1):**
  * **A안 (티스토리 홈 커버 기능 활용):** 원본 제안 방식. 커버 편집 UI에서 드래그로 순서 변경. 단, `index.xml`의 커버 정의 스펙·자유도 검증이 선행되어야 함.
  * **B안 (스킨 옵션 프리셋):** 커버가 요구사항을 못 받쳐줄 경우. 스킨 옵션 SELECT로 홈 구성 프리셋(예: `캐릭터 우선` / `로그 우선` / `공지 우선`)을 고르면 JS가 섹션 순서를 재배치. 자유도는 낮지만 확실히 동작하며, v1.2.0의 섹션 조립 로직을 거의 그대로 쓸 수 있음.

### 3.2. 로그 백업 렌더러 (첨부파일 방식) — 최우선 개발 항목

* **문제:** 긴 HTML 로그를 티스토리 에디터에 붙여넣을 때의 렉·튕김.
* **해결:** 유저는 본문에 코드를 붙여넣지 않는다. 코코포리아 / 롤20에서 내보낸 로그 파일을 게시글에 **'파일 첨부'**만 하고 발행한다.
* **작동:** 프론트엔드 JS가 첨부파일 URL을 `fetch` → `DOMParser`로 파싱 → 채팅 로그 UI로 렌더링. (참고 UI: factory-roll20-machine)
* **파서 구조:** 툴별 어댑터 방식.
  * `코코포리아 어댑터` — 발화자명 / 본문 / 색상 / 탭 추출
  * `롤20 어댑터`
  * `공통 폴백` — 인식 실패 시 원문을 정돈된 텍스트 블록으로 출력 + 원본 다운로드 링크 노출 (**절대 빈 화면을 내지 않는다**)
* **뷰어 UX:**
  * 발화자별 색상·정렬, 다이스 롤 결과 강조, 잡담/시크릿 탭 접기
  * 긴 로그 대비 **분할 렌더링** (초기 N건 + '더 보기') — 수천 줄을 한 번에 DOM에 넣지 않는다
  * 로그 본문 판독용 최소 타이포그래피(줄 간격·자간·발화 단위 여백)를 여기서 정의
* **보안:** 외부 파일 내용을 `innerHTML`로 직접 주입하지 않는다. 텍스트 노드 기반 조립 또는 허용 태그 화이트리스트를 거친다.
* ⚠️ **선결 검증 필요:** 첨부파일 fetch의 CORS 허용 여부 및 티스토리 첨부 가능 확장자. §4.1 참조.

### 3.3. 캐릭터 및 관계 전시

* **캐릭터 갤러리:** 캐릭터 카테고리 진입 시 증명사진(두상/흉상) 갤러리 노출, 클릭 시 상세 게시글로 이동.
* **게시글 내 정보란:** 캐릭터 이름 / 소속 / 출신 룰 / 다녀온 시나리오 / 등장 로그 링크.
  → HTML 편집 없이 §3.5의 표기 규칙으로 입력하면 JS가 정보 테이블로 조립.
* **다인(1~4인) 페어 템플릿:** 유저가 에디터에서 텍스트와 이미지만 넣어도 CSS(타로카드 프레임, 찢어진 종이 등)가 씌워지도록 극도로 단순화된 마크업 양식 제공.
  * 인원수는 이미지 개수로 자동 판정 → 1/2/3/4인 레이아웃 자동 전환 (유저가 인원수를 지정할 필요 없음)
* **본문 판독성:** 캐릭터 소개 본문에 한해 줄 간격·문단 구분 정비. (집필용 템플릿이 아닌, 읽기용 최소치)

### 3.4. TRPG / 갠홈 과몰입 기믹 (핵심 셀링 포인트)

1. **보호글 컨셉 연출:** 실제 티스토리 비밀글 기능을 유지해 검색/노출은 차단하고, 비밀번호 입력 화면만 *"이 세션의 진상을 열람하시겠습니까?"* 류의 컨셉 UI로 덮는다.
   → v1.2.0에 `.protected-form-wrap` / `.card-protected-overlay`가 이미 존재. **문구·연출만 교체.** 단 `[##_article_password_##]` 치환자와 폼 구조는 반드시 보존 (변경 시 인증 실패).
2. **이중 프로필 / 시크릿 플립:** 증명사진·텍스트 Hover 시 반전되어 이면 설정이 드러나는 CSS 효과.
3. **스포일러 블라인드:** 본문 텍스트를 `█████`로 가리고 클릭/드래그 시 해제. 입력은 §3.5 규칙으로.
4. **접힘글 커스텀:** 티스토리 기본 '더보기' 문구를 스킨 옵션에서 2종(`[경고형 ⚠️]`, `[미니멀 실선형]`)으로 선택.
5. **Hover 인터랙션:** 미니멀리즘 유지 전제. 아래 레퍼런스에서 **효과를 2~3종으로 고정**해 스킨 전체에 일관 적용한다 (효과 백화점이 되면 미니멀 톤이 깨짐).
   * [Colorion Text Effects](https://kinetics.colorion.co/?ref=text-effects.colorion.co)
   * [UIverse Elements](https://uiverse.io/elements)
   * [CanvasUI VHS](https://canvasui.dev/docs/components/vhs)
   * **모바일 필수 대응:** Hover가 없는 환경에서는 tap 토글 또는 기본 노출로 폴백. Hover에만 정보를 담지 않는다.

### 3.5. 에디터 무코딩 표기 규칙 (신설)

"유저가 HTML 모드를 열지 않게 한다"는 원칙을 실제로 성립시키는 장치. v1.2.0이 이미 쓰고 있는 **제목 태그 파싱** 관례(`[OPEN]` `[CLOSE]` `[PRICE:]` `[SUB:]`)를 확장한다.

* **제목 태그** — 글 제목에 입력, JS가 파싱 후 제목에서 제거
  * `[SUB:부제]` (현행 유지), `[LOG]` / `[CHAR]` (카테고리 라우팅 실패 시 백업 판정용)
* **본문 첫머리 정보 라인** — 그냥 텍스트로 한 줄씩 치면 정보 테이블로 변환
  ```
  소속: 제3관측반
  룰: 크툴루의 부름 7판
  시나리오: 「해안선의 밤」
  ```
* **인라인 규칙** — 에디터에서 순수 텍스트로 입력
  * `||가려질 내용||` → 스포일러 블라인드
  * `>> 발화자: 대사` → 인용/대화 블록
* **원칙:** 규칙을 안 써도 글은 평범하게 정상 출력된다. 규칙은 항상 선택적 강화이지 필수 문법이 아니다.

## 4. 제약 및 선결 검증 과제

설계를 확정하기 전에 실기로 확인해야 하는 항목. 이 결과에 따라 §3.2와 §3.1의 구현안이 갈린다.

### 4.1. 최우선 검증 (§3.2 로그 렌더러의 성립 조건)

| # | 검증 항목 | 확인 방법 | 실패 시 대안 |
| --- | --- | --- | --- |
| 1 | 티스토리가 `.html` 파일 첨부를 허용하는가 | 테스트 블로그에 첨부 업로드 | `.txt`로 확장자 변경 안내 (내용이 HTML이어도 `DOMParser` 파싱 가능) |
| 2 | 첨부파일 CDN이 **CORS를 허용**하는가 | 발행된 글에서 `fetch(첨부URL)` 실행 | 첨부 렌더링 불가 → 대안 3 검토 |
| 3 | 스킨 치환자로 첨부 목록/URL을 얻을 수 있는가 | 치환자 출력 확인, 없으면 본문 내 첨부 링크 DOM 파싱 | 본문 `<a>` 링크 파싱 |
| 4 | 대용량 로그 렌더링 성능 | 5,000줄 이상 실측 | 분할 렌더링 (§3.2) |

**2번이 실패할 경우의 대안 3안** — 유저가 로그 파일을 외부(Gist 등 CORS 허용처)에 올리고 URL만 본문에 적는 방식. 단계가 늘어나므로 최후 수단.

### 4.2. 그 외 확인 항목

* 티스토리 홈 커버의 커스텀 모듈 자유도 (§3.1 A안 성립 여부)
* 티스토리 에디터 '접힘글' 블록의 실제 마크업 구조 (§3.4-4)
* 티스토리 하단 표기·툴바 은닉이 서비스 정책에 저촉되지 않는 범위

## 5. 단계별 릴리스 계획

원본 제안서 전체를 한 번에 내면 검증되지 않은 기능이 뭉텅이로 묶여 나간다. 3단계로 분할한다.

* **v2.0 — 기반**
  §2 라우팅, §3.2 로그 렌더러, §3.3 캐릭터 갤러리 + 정보란, §3.5 표기 규칙
  → 이 스킨의 존재 이유에 해당하는 최소 묶음
* **v2.1 — 몰입 연출**
  §3.4 기믹 전체 (보호글 연출 / 플립 / 블라인드 / 접힘글 / Hover)
* **v2.2 — 홈 구성**
  §3.1 모듈형 홈 (커버 검증 결과 반영), 페어 템플릿 확장

## 6. 작업 시 지시사항

* **에디터 의존도 낮추기:** 유저가 HTML 모드에서 코드를 치게 만들지 않는다. 모든 입력은 §3.5 규칙 또는 파일 첨부로 해결한다.
* **디자인 톤앤매너:** 불필요한 테두리·그림자·설명 텍스트를 배제하고, 여백과 Z-index 교차를 활용한 미니멀리즘을 유지한다.
* **폴백 우선:** 어떤 파싱·fetch·규칙도 실패할 수 있다. 실패 시 반드시 "평범하지만 깨지지 않은 화면"으로 떨어진다.
* **착수 산출물:** 이 문서를 바탕으로 ① 로그 백업 첨부파일 렌더링 스크립트 구상, ② 전체 CSS 레이아웃(그리드/템플릿) 마크업 구조를 먼저 제시한다. 단, **§4.1 검증이 선행**되어야 ①의 전제가 확정된다.
